# Data and Assets

Everything this project ships as data, where it came from, what licence it is
under, and whether any code actually reads it.

Nothing is fetched at runtime by the application. Every asset the GUI needs is
compiled into the binary with `include_str!` or `include_bytes!`, so there is no
data directory to install and no path to get wrong.

## Compiled-in assets

| Asset | Size | Compiled in at | Licence |
|---|---|---|---|
| `data/igrf14coeffs.txt` | 45 KB | `src/mag/igrf.rs` | Public, IAGA V-MOD |
| `app/src/assets/fof2_grid.tsv` | 41 KB | `app/src/fof2.rs` | Generated by this project, GPL-3.0 |

| `app/src/assets/ne_50m_lakes.shp` | 332 KB | `app/src/coastline.rs` | Natural Earth, public domain |

The shapefiles live under `app/src/` rather than a top-level `data/` directory
because `include_bytes!` resolves relative to the source file, and keeping them
adjacent to the one module that reads them is what stops the path drifting.

### IGRF-14 coefficients

`data/igrf14coeffs.txt`, IAGA V-MOD. Schmidt semi-normalised spherical-harmonic
g and h coefficients to degree 13, in nanotesla, at epochs 1900.0 through 2025.0
in five-year steps. DGRF (definitive) values through 2020, IGRF for 2025, plus a
2025 to 2030 secular-variation column in nT per year to degree 8.

Parsed at startup into `Igrf`, valid over 1900.0 to 2030.0.
`IGRF_REFERENCE_RADIUS` is 6,371,200.0 m, which is the IGRF reference radius and
**not** the Earth radius used elsewhere in the project. Do not unify them.

Consumed downstream by `app/src/scenario.rs`, `app/src/coverage.rs`,
`benches/trace.rs` and `tests/magnetoionic_3d.rs`.

### The foF2 climatology grid

`app/src/assets/fof2_grid.tsv`. Generated by
`app/src/bin/gen_fof2_grid.rs` and checked in.

**This is not CCIR, URSI or IRI data.** Its layout follows the operational idiom
but its values come from this project's own order-of-magnitude climatology. The
full provenance statement is in
[Ionosphere Model](Ionosphere-Model.md#provenance-of-the-bundled-grid-read-this)
and repeated in the file's own header.

The generator is the provenance. Running it reproduces the file exactly, and
`fof2::tests::bundled_grid_matches_its_generator` fails if the two ever
disagree. That test is the reason it is safe to check generated data in.

### Natural Earth coastlines

`ne_50m_land.shp` and `ne_50m_lakes.shp`, Natural Earth 1:50m physical vectors,
public domain.

Note that only the `.shp` geometry files are shipped, not the accompanying
`.dbf` attribute or `.shx` index files. `coastline.rs` needs polygon geometry
only; it does not read any attribute, so the other files would be dead weight.

Two limitations, both surfaced in the code:

- It classifies **water versus land only**. Not sea state, not ice, not terrain.
- At 1:50m resolution small features are absent, so a point a few kilometres
  from a coast can classify as the wrong side. Known reference points are pinned
  by test.

## Vendored but unused: `data/nequick/`

Thirteen files, about 600 KB. **No code in this repository reads any of them.**

They are staged so that a future NeQuick-G backend has its reference data
already vendored and already licensed, and so the provenance is recorded while
it is still verifiable. `data/nequick/README.md` says this in the directory
itself, so nobody has to grep the source to find out.

| File | Contents |
|---|---|
| `ccir11.txt` to `ccir22.txt` | Monthly CCIR coefficient maps. The number is month plus 10, so `ccir11` is January and `ccir22` is December. Each holds 2858 values: 1976 foF2 coefficients as `F2[2][76][13]`, then 882 M(3000)F2 coefficients as `Fm3[2][49][9]`. The leading dimension is the low/high solar activity pair, R12 = 0 and R12 = 100. |
| `modipNeQG_wrapped.txt` | Modified dip latitude grid, 39 by 39 = 1521 values in degrees. A 5 degree latitude by 10 degree longitude core, pole- and longitude-wrapped so a third-order 4 by 4 interpolation needs no edge cases. Derived from IGRF around epoch 2001. |
| `_SOURCE_AND_LICENSE.txt` | Provenance and licence. Must stay with the data. |

**Licence: EUPL v1.2, (C) European Union 2019.** This is not the GPL-3.0 that
covers the rest of the repository; it is one of the exemptions the top-level
`LICENSE` refers to. Article 5 of the EUPL requires the notice to travel with
the data, so `_SOURCE_AND_LICENSE.txt` must not be deleted or separated from the
coefficient files. If this data is ever removed, remove the whole directory at
once.

Extracted from the Annex C attachments of the European Commission's "Galileo
Ionospheric Correction Algorithm" ICD, Issue 1.2, September 2016. Byte-identical
to the NeQuickG JRC reference implementation. The CCIR values agree with
ITU-R P.531-16 to 5.6e-7 relative.

**Do not confuse this with `fof2_grid.tsv`.** These files are real CCIR data
that nothing uses; the bundled grid is synthetic data that everything uses.

## Fetched at runtime, by harnesses only

Never by the GUI. See
[Validation Harnesses](Validation-Harnesses.md#network-access).

| Source | Endpoint | Licence and conditions |
|---|---|---|
| WSPRnet archive | `db1.wspr.live` | Public ClickHouse endpoint, volunteer-run |
| SILSO | `www.sidc.be/SILSO/DATA/EISN/EISN_current.csv` | Estimated international sunspot number |
| NOAA SWPC | `services.swpc.noaa.gov/json/solar-cycle/observed-solar-cycle-indices.json` | US Government, public domain |
| GIRO DIDBase | fetched separately into `corpus/ionosonde.tsv` | CC-BY-NC-SA 4.0, station operators must be acknowledged |

The GIRO condition is the one that binds a downstream publication: any published
use of those numbers must carry the licence and acknowledge each contributing
station's operator. The corpus file header carries both.

## What is deliberately not committed

- **Build output.** `target/` is ignored. So is any generated WebAssembly or JS;
  a 12.7 MB `.wasm` and its glue used to be committed and were removed with the
  web target.
- **`corpus/`.** Fetched data with its own licences, and it goes stale.
- **`graphify-out/`.** Knowledge-graph tooling output.
- **`.idea/`.** Editor configuration.

Generated data **is** committed in exactly one case, `fof2_grid.tsv`, and only
because a test proves it still matches its generator.
